# Contributing

Contributions are welcome.

## Guidelines

- Keep sample data public, synthetic, or explicitly approved for redistribution.
- Do not commit credentials, connection strings, tenant-specific endpoints, private workspace names, or customer data.
- Keep KQL scripts runnable as standalone assets where practical.
- Document any new table, function, update policy, or sample dataset.
- Include validation queries for meaningful changes.

## Local review checklist

Before opening a pull request:

1. Confirm KQL scripts run in a Fabric KQL database or query window.
2. Confirm documentation links resolve.
3. Search for secrets and tenant-specific values.
4. Confirm sample data includes a safety disclaimer when applicable.
